Routers are in `packages/api/src/routers` and are mounted in
`routers/index.ts`. Access levels:

- **public**: `publicProcedure`, anyone.
- **admin**: `adminProcedure`, the owner only (see [Authentication](/architecture/authentication)).

**Edge TTL** is the edge cache lifetime from `PROCEDURE_CACHE_POLICY`; "—" means
the response is never cached. Mutations are never cached.

## Common errors

Every procedure can return these codes (see [Runtime](/architecture/runtime#errors)):

| Code | When |
| ---- | ---- |
| `BAD_REQUEST` | Zod input validation failed (`data.zodError` lists fields), a check or not-null constraint failed, or a procedure-specific rule was broken. |
| `UNAUTHORIZED` | Admin procedure without a session. |
| `FORBIDDEN` | Admin procedure with a session that is not the owner. |
| `NOT_FOUND` | `byId`, `bySlug`, `forEdit`, `update`, or `delete` matched no row. |
| `CONFLICT` | A unique or foreign-key constraint failed: a duplicate name, or a delete blocked by references (see [deletion behavior](/architecture/domain-model#deletion-behavior)). |
| HTTP `429` | Not a tRPC error: the HTTP handler rejects the request before tRPC runs when the per-IP limit for uncached reads or mutations is exceeded. |
| `INTERNAL_SERVER_ERROR` | Anything else; the message is generic and the details are in the Worker log. |

Every error carries `data.userMessage`: the message of a 4xx rejection, which
procedure code or `normalizeProcedureError` wrote and is safe to show, or `null`
for 5xx and validation errors. The dashboard shows it in error toasts; the
public site shows only its own Portuguese messages.

## Shared input rules

From `packages/api/src/input-schemas.ts`:

| Schema | Rule |
| ------ | ---- |
| `positiveInt` | safe integer ≥ 1 (all IDs) |
| `page` / `limit` | 1–1000, default 1 / 1–100, default 20 |
| `nameText` | trimmed, 1–160 characters |
| `searchText` | trimmed, up to 120 characters |
| `contentText` | up to 500,000 characters (Markdown) |
| `rating` | integer 0–4000 |
| `isoDate` | `YYYY-MM-DD` |
| `httpUrl` | `http` or `https` URL, up to 2,048 characters |
| `imageUrl` | a media path (`/api/media/...`) or an `httpUrl` |
| `optionalHttpUrl` | an `httpUrl` or an empty string |
| `filterArray` | up to 50 strings of 1–80 characters |

Update procedures take `{ id, ...fields }`, where every field is optional and
`nullable` fields accept `null` to clear them. Create, update, and delete return
the affected rows (`.returning()`), except where noted.

There is no player delete procedure; set `active: false` instead.

### Player links

`playersToTitles`, `playersToRoles`, and `playersToInsignias` share one shape:

| Procedure | Access | Input | Output |
| --------- | ------ | ----- | ------ |
| `<router>.listByPlayer` | admin | `{ playerId }` | Linked rows |
| `<router>.link` | admin | `{ playerId, titleId \| roleId \| insigniaId }` | Created link; `CONFLICT` if already linked |
| `<router>.unlink` | admin | same as `link` | Deleted link; `NOT_FOUND` if absent |

### Rating update

| Procedure | Access | Input | Output |
| --------- | ------ | ----- | ------ |
| `playersTournament.linkWithRating` | admin | `{ playerId, tournamentId, variation (−4000…4000), ratingType }` | `[{ id, oldRating, variation }]` |
| `playersTournament.listByPlayer` | admin | `{ playerId }` | History rows in chain (`id`) order, with tournament |
| `playersTournament.listByTournament` | admin | `{ tournamentId }` | The tournament's results, with player |
| `playersTournament.correctVariation` | admin | `{ id, variation }` | `{ id, oldRating, variation, ratingType, rating }`; `rating` is the player's new current rating |
| `playersTournament.remove` | admin | `{ id }` | `{ id, ratingType, rating }` |
| `playersTournament.revertTournament` | admin | `{ tournamentId }` | `{ reverted }`, the number of results removed |

Errors: `NOT_FOUND` (player, tournament, or result), `BAD_REQUEST` (rating type
differs from the tournament's, or a rating would leave 0–4000), `CONFLICT`
(`linkWithRating` only: the rating changed concurrently, or this player already
has history for the tournament). Corrections keep the history chain intact; see
[corrections](/architecture/domain-model#corrections).

## Media

| Procedure | Access | Input | Output |
| --------- | ------ | ----- | ------ |
| `images.upload` | admin | `{ kind: players\|posts, mime: image/jpeg\|png\|webp, data: base64 }` | `{ url: "/api/media/<kind>/<uuid>.<ext>" }` |

Upload errors: `BAD_REQUEST` for an image under 1 KB, over 5 MB, or whose bytes
do not match `mime`. See [Media](/architecture/media).
