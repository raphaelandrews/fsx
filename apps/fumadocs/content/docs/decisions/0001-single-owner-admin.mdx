---
title: "ADR 0001: Single-Owner Administration"
description: Authorization model and protected export access.
---

- Status: Accepted
- Date: 2026-10-01

## Context

FSX currently has one operational owner. A generic role model would add policy
surface without an established second administrator. Bulk exports and identity
editing must remain protected even when their underlying rows also appear on
public pages.

## Decision

Every administrator procedure checks the configured GitHub identity on every
request. The identity is the numeric GitHub account ID (`GITHUB_USER_ID`),
matched against Better Auth's `account.account_id`, because logins can be
renamed and reclaimed by another person. Sign-in rejects every other GitHub ID
before any user, account, or session row is written. `GITHUB_USERNAME` and
first-user ownership remain only as fallbacks when no ID is configured.

Swiss Manager export is administrator-only; authenticated and mutation tRPC
responses are marked `no-store`. Public routes continue to use minimal
public projections. Any future second administrator requires an explicit role
and permission model plus session invalidation on privilege changes.

## Consequences

Authorization remains centralized and straightforward. Administrators share the
same permissions until a reviewed role model is introduced.

## Update 2026-10-03

The Swiss Manager export is public again at `/swiss-manager`, birth dates
included, at the federation's request: arbiters download it to pair tournaments
and Swiss Manager uses birth dates for age categories. The page fetches the
roster only when the export button is clicked, so page HTML never carries it;
`swissManager.list` is edge-cached for 300 seconds and no longer logged as an
administrator export.
