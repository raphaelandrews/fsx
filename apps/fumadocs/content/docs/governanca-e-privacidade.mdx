# Governance and Privacy

Player profiles may contain a name, nickname, birth date, sex, location,
FIDE/CBX identifiers, image, and rating history. Public projections include the
player's name, rating, title, club/location, image, active/verified state, and
CBX/FIDE IDs displayed on the profile. Birth date, sex, and description are
administrator-only. Public ratings filters apply birth-date/sex predicates on
the server without returning those values.

The configured GitHub identity is the sole administrator. That administrator
may correct identity/profile fields and manage ratings; only rating changes that
come from a tournament workflow are written to the rating-history table. Never
delete or rewrite rating history to make a correction. Before deleting a player,
check tournament, circuit, cup, and event relationships; retain the player record
when a historical relationship requires it.

Better Auth sessions expire after seven days and refresh their expiry after one
day of use. Expired sessions are not retained as active credentials. Accounts
are not removed automatically; review dormant accounts annually and remove an
account only after confirming the owner request and invalidating its sessions.

Logs must use request IDs, procedure names, and safe metadata without payloads,
tokens, IP addresses, secret URLs, spreadsheet contents, or unnecessary personal
data. Backups and the Swiss Manager export require the single-owner administrator
check; authenticated/mutation tRPC responses use `Cache-Control: no-store`.
Backups are stored outside the repository with owner-only filesystem permissions
and a 90-day default retention window. The Swiss Manager export audit log records
administrator ID, procedure, request ID, timestamp, result, and row count only.
Rate-limit records contain the client IP as the limiter key. A scheduled Worker
removes windows older than ten minutes every fifteen minutes; access to aggregate
row counts and window ranges is administrator-only.
The rating-import screen stores its local result history (player name/ID and safe
error category) in browser `localStorage`; the administrator can clear it from
that screen. Server request/error logs do not store this history.

Rating corrections must preserve history. Profile removal or correction must be
authorized by the administrator and checked against historical relationships
before data is deleted. Keep a documented reason for manual identity/profile
corrections in the operational record, not in public fields or request logs.
