# ADR 0004: Atomic D1 Rating Updates

- Status: Accepted
- Date: 2026-10-01

## Context

Cloudflare D1 rejects explicit `BEGIN` transactions from the Worker API. A
rating write and its tournament-history row must nevertheless succeed or fail
together, and two concurrent requests must not overwrite one another.

## Decision

Read the stored rating and validate the requested tournament, then submit the
compare-and-set player update and conditional history insert together with
Drizzle's D1 `batch()` API. The update predicate requires the rating value used
for the calculation; the following history insert is guarded by SQLite's
`changes()` result. D1 rolls the entire batch back when the history insert
violates a constraint. A zero-row update returns `CONFLICT`.

## Consequences

This uses a D1-supported atomic batch rather than a Drizzle `transaction()`
that emits unsupported `BEGIN` statements. A real Miniflare D1 integration test
covers success, duplicate-registration rollback, and concurrent updates.
